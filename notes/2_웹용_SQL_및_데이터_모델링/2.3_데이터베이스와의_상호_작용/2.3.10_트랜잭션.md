# 트랜잭션

## 개요
**트랜잭션(Transaction)** 은 데이터베이스에서 수행되는 **하나의 논리적 작업 단위(Unit of Work)** 이다.  
모든 데이터 변경(삽입, 수정, 삭제)은 반드시 트랜잭션을 통해 수행된다.

> 👉 관계형 데이터베이스(RDBMS)는 “트랜잭션 기반 시스템(Transactional System)”이다.  
> 즉, 모든 데이터 변경은 트랜잭션이라는 단위로 관리된다.

<br>

## 트랜잭션의 정의

| 항목 | 설명 |
|------|------|
| **트랜잭션(Transaction)** | 데이터베이스에서 실행되는 **원자적(Atomic)** 인 작업 단위 |
| **세션(Session)** | 여러 트랜잭션을 포함할 수 있는 연결(Connection) 단위 |
| **명령어 예시** | `INSERT`, `UPDATE`, `DELETE` 같은 데이터 변경 작업 |

하나의 트랜잭션은 다음과 같은 일련의 명령을 포함할 수 있다.

```sql
BEGIN;               -- 트랜잭션 시작
UPDATE users SET age = 25 WHERE id = 1;
DELETE FROM orders WHERE id = 101;
COMMIT;              -- 모든 명령 성공 시 커밋(저장)
-- 또는
ROLLBACK;            -- 중간에 실패 시 전체 취소
```

<br>

## 트랜잭션의 동작 방식

### 1) 트랜잭션 시작
- 클라이언트가 데이터베이스에 연결 후, 특정 작업 단위를 시작한다.
(`BEGIN TRANSACTION`)

### 2) 작업 수행
- 여러 SQL 문 (`INSERT`, `UPDATE`, `DELETE`) 이 순차적으로 실행된다.

### 3) 결과 확인 및 처리
- 모든 작업이 성공하면 `COMMIT` 으로 데이터베이스에 영구 저장.
- 중간에 실패하면 `ROLLBACK` 으로 모든 작업 취소.

### 4) 세션 종료 시점
- 세션이 종료되면 트랜잭션도 닫히며 연결이 해제된다.

<br>

## 트랜잭션이 필요한 이유
- 데이터베이스는 언제든 실패할 수 있다.
  <br>서버 다운, 네트워크 오류, 코드 예외 등으로 인해 작업이 절반만 수행되는 위험이 있기 때문이다.

- 트랜잭션은 다음과 같은 문제를 방지한다.

  | 상황    | 트랜잭션이 없을 경우                  | 트랜잭션이 있을 경우                |
  | ----- | ---------------------------- | -------------------------- |
  | 은행 송금 | A 계좌에서 돈이 빠졌는데 B 계좌에 입금이 안 됨 | 두 작업 모두 성공해야만 커밋됨 (원자성 보장) |
  | 주문 처리 | 주문 레코드는 생겼지만 결제 기록은 없음       | 둘 중 하나라도 실패 시 전체 롤백        |

> 핵심 포인트:  
> 트랜잭션은 “모두 성공(All-or-Nothing)” 또는 “모두 취소(All-or-Nothing)” 원칙을 따른다.

<br>

## 트랜잭션의 장점
### 1) 일관성 유지 (Consistency)
- 데이터가 항상 유효한 상태를 유지

### 2) 원자성 (Atomicity)
- 전체가 하나의 단위로 실행 — 일부만 성공 불가

### 3) 격리성 (Isolation)
- 동시에 여러 트랜잭션이 실행되어도 서로 간섭하지 않음

### 4) 영속성 (Durability)
- 커밋된 데이터는 시스템이 꺼져도 유지됨

이 네 가지를 묶어서 **ACID 속성**이라 부른다.

<br>

## ACID 속성 요약
| 속성                        | 설명                | 예시                     |
| ------------------------- | ----------------- | ---------------------- |
| **A – Atomicity (원자성)**   | 모두 실행되거나 모두 취소됨   | 송금 중 한 단계라도 실패 시 전체 취소 |
| **C – Consistency (일관성)** | 데이터 무결성 유지        | 잔액이 음수가 되지 않음          |
| **I – Isolation (격리성)**   | 동시에 실행되어도 결과가 독립적 | 여러 유저가 동시에 주문해도 문제 없음  |
| **D – Durability (영속성)**  | 커밋 후에는 영구히 저장     | 시스템 재시작 후에도 반영된 상태 유지  |

<br>

## 핵심 정리
- 트랜잭션은 데이터베이스 작업의 기본 단위이며,
모든 데이터 변경(삽입, 수정, 삭제)은 트랜잭션으로 묶여 수행된다.

- 트랜잭션은 세션(Session) 안에서 실행되며, 여러 트랜잭션이 하나의 세션 안에 존재할 수 있다.

- 트랜잭션은 실패 시 전체를 롤백(Rollback) 하고, 성공 시 커밋(Commit) 한다.

- 트랜잭션의 신뢰성과 안정성을 보장하는 원칙이 바로 ACID 속성이다.

### 요약

- 트랜잭션 = 데이터베이스 작업의 “논리적 묶음”
- 모두 성공 → COMMIT
- 하나라도 실패 → ROLLBACK

- ACID 원칙을 따름으로써,
<br>데이터베이스는 장애가 발생하더라도 항상 일관되고 신뢰 가능한 상태를 유지한다.
